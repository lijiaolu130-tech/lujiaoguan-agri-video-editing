# 发布通道与风控细则

## 0. 红线（最高优先级）

1. 成片只进**草稿箱/私密存货**，禁点公开发表
2. 公开发布必须：用户当次明确授权 + 06:00–20:00 窗口 + 2 小时间隔 + 每天最多 8 条
3. 清空/删除任何已发布内容前，必须先列出确切清单经用户确认

## 1. 抖音私密存货流程

```
upload 页 → input[type=file] set_input_files → 等转码（出现「重新上传」或时长）
→ 文案 contenteditable（Meta+A+Backspace 清空 → execCommand insertText 整段插入，含 #标签）
→ 可见范围「仅自己可见」（点 label 本体 + data-checked 断言）
→ 点「发布」→ 处理确认弹层（只点 确认/确定，绝不裸点「删除」）
```

- 登录：cookie 直登必失败（DBSC 设备绑定）→ 扫码一次，持久 profile 复用
- 草稿按钮叫「**暂存离开**」，前面有「我知道了」弹层挡路，先关弹层
- 页面跳转成功**≠服务端入库**（见 §3 验证）

## 2. 当日配额（2026-10-03 实测铁律）

- **~30 条/日是硬顶**（含所有发布动作：草稿+私密）
- 首轮 24 条/小时仍超 → 被拒 10 条；随后 7 分钟/条慢补 10 条**全部再拒**，列表纹丝不动
- 超配额后当天任何间隔都无效，页面照常显示「发布成功」
- 对策：一天 ≤30 条；到顶立即停手（继续刷会加重风控）；次日先验证冷却解除再补

## 3. 发布验证（指纹差集法）

页面层判定不可信。唯一可信验证：

1. 打开创作者中心「内容管理」列表（**无限滚动**，不是分页——点「下一页」按钮会失败）
2. 滚动累积法：每轮 `window.scrollTo` 到底 + 容器 scrollTop 拉满 + 抓 `body.innerText`，
   文本长度连续 4 轮不变即到底；每轮从 innerText 按「编辑作品」分段提取（标题+日期+可见性）
3. 用**标题前 8 字指纹**与发布队列做差集 → 命中=入库；MISS=被静默拒收
4. ⚠️ DOM 向上爬卡片的方法在管理页会失效（抓不全），innerText 累积法可靠
5. 补发漏网条目：次日先枚举列表确认冷却解除，再 5–10 分钟/条慢速补

## 4. 抖音控件细节

- 可见范围：`label.radio-d4zkru[data-checked]` 包 `input[type=checkbox]`
  → **点 label 本体**（点 span 无效），断言 `data-checked==='true'` 且「公开」为 false
  → **没有断言的发布脚本会误公开**（踩禁发红线），抄脚本必检查这一条
- 删除卡片定位：从「删除作品」链接向上找第一个同时含「私密+日期+不含已发布」的祖先；
  确认弹层只点「确认/确定」；**每删一条必须重扫 DOM**（列表重排，复用旧坐标会连点空气）

## 5. 视频号（vqq）通道

- 走 save_draft 流程：直连 create → 上传 → 文案 → 原创声明弹层 → 保存草稿，约 2 分钟/条
- 命令必须**扁平**：`{"cmd":"exec","file":"steps/save_draft.py","dry":false,"targets":[...]}`
  —— targets 嵌在 "spec" 里会静默空跑
- 入箱前用已发布列表逐页比对主题，防重复推送

## 6. 多会话协作

- 同一账号状态文件（如发布进度 state）被多个会话共享时，**读写都要做格式规范化**
  （dict/list 双兼容），否则一边写 list 一边假设 dict 直接崩
- 通道分工要显式声明（如：本会话占抖音通道、并行会话占视频号通道），写 HANDOFF 文件
- 接管他人脚本前先修它的断言缺失（无私密断言的发布脚本会误公开）
