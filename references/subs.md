# 字幕规范与对齐算法

## 1. 硬参数

| 项 | 值 |
|---|---|
| 每卡字数 | ≤13 字/行（方言口语可放宽到 20，用户实测「拆太碎」反馈后调宽） |
| 行数 | ≤2 行，一句话拆两张卡比长卡强 |
| 竖屏位置 | Alignment=2（底中），MarginV=155，MarginL/R=64 |
| 字号 | 正文 66 / 待核词 62 / 顶卡标题 86 / 副标 66 / 花字 44 |
| 颜色 | 正文白字黑边 / 待核词黄(&H0061DBFF 类) / 标题金 0xFFDB61 / 花字绿 0xA6EBBF |
| 字体 | 书法体（方正启功行楷）做标题，粗黑体做正文；烧录必须带 fontsdir |

## 2. 错字替换表（FIX_WORDS）

- **长词排前面**：`("骨抗门","果挂稳")` 必须在 `("骨抗","果挂")` 之前，否则短词先命中毁掉长词
- **只替换有证据的**：拿不准的一律标待核，不许猜
- 每条替换必须注释出处（哪条片、哪个时间码、怎么实证的），例如：

```python
("枝鸭", "枝丫"),        # ep04 0:25「然后你看这一个枝鸭哦」抽帧实证
("嗯很甜", "很甜"),       # ep06 1:18「嗯很甜」烧录字幕实证（2026-10-04）
```

## 3. 切卡陷阱（大坑）

**如果替换发生在「按 N 字切卡之后」，跨卡的长句永远匹配不上。**
实测案例：原文「保温,保水,保湿」要改「保水,保肥」，但切卡后变成
「…保温保水」+「保湿的…」两张卡 → 必须补切卡后形态的两条：

```python
("保温保水", "保水保肥"),
("保湿的这种", "这种"),
("保温,保水,保湿", "保水,保肥"),   # 转写原文带逗号，无逗号词根也匹配不上
```

教训：**替换应尽量放在切卡之前**（prepare 阶段的 fix 注入层），FIX_WORDS 只兜底。

## 4. 逐字高亮（token 钉字）

whisper word 级时间戳 → 把每张卡的每个字钉到 token 时刻：

1. `norm()`：只保留汉字（去标点/空格），转写侧与字幕侧同样处理
2. `difflib.SequenceMatcher` 找最长公共串定位每张卡在 token 序列里的位置
3. 失配判据（三条同时满足才算命中）：
   - 公共串 ≥2 字
   - 覆盖率 ≥0.40（太低是错位匹配）
   - **位置连续性**：本卡起点 − 上一卡终点 ≤3.5s（字幕卡是顺序的，跳几秒就是匹配飞了）
4. 未命中卡：中间卡在左右邻居间**按字数比例插值**；末尾一批单独铺在真实语音区间上（否则滚动膨胀、尾巴甩出音频）
5. 收尾：单调化 + 最短 0.30s + 接缝 ≤0.55s 补齐 + **越界夹紧到音频长度**
6. 方言素材繁体问题：prompt 强制简体 + `to_simple()` 繁简转换双保险

## 5. 语气词处理口径

| 情形 | 处理 |
|---|---|
| 孤立语气词成卡（「嗯。」「啊，」） | 整卡不烧 |
| 句首起势（「嗯，那芽点…」） | fix 删「嗯，」，字幕从实词起 |
| 句尾语气（「枝丫哦」「太香了」） | 保留（自然口语，不碍事） |
| 声音里有但字幕没烧 | 不动（音频手术成本高收益低） |
| 无证据听不清 | 字幕写「听不清，请网友翻译」，禁止硬猜 |

## 6. 花絮过滤

- 特征词表：录了没有/摄影/镜头/重来/收音/麦克/放那儿/等一下…
- 段首 `-` 前缀是 whisper 的「换人说话」标记，**判定对谈要用剥离前原文**，烧字幕用剥离后文本
- 拍摄对话（对词/走位指令）是**画面问题**：只掐字幕不算修，要剪画面
